# 指针式仪表读数方法设计与数据审计

审计日期：2026-08-21
状态：方法设计，不包含读数实现修改
比赛依据：`XA-202622北京普龙科技有限公司-面向边缘端多形态指针式仪表通用读数方法及泛化应用研究比赛方案(1).pdf` 第 6-8 页。

## 1. 结论先行

现有 `best.pt` 和 YOLO 标签可以直接复用为 **仪表定位与 ROI 裁剪层**，无需继续训练 YOLO；但它们不能直接提供读数。当前 1,040 张图像只有单类 `Dashboard` 检测框，没有轴心、指针、刻度、角度、量程、单位或读数标注。

可落地的读数路线应是：

```text
冻结 YOLO 定位
  -> 几何归一化
  -> 指针/轴心/刻度的传统视觉提取
  -> 已知仪表模板匹配，或 OCR 自动标定
  -> 角度/位置到数值的确定性映射
  -> 质量门控、时序滤波与结构化输出
```

这条路线符合比赛要求的“深度学习与传统机器视觉结合”：YOLO 负责鲁棒定位，OpenCV 几何负责可解释读数，OCR 只在新仪表标定或模板失配时运行。端侧连续读数不必每帧执行 OCR。

当前 `仪表盘读数标注.md` 不能直接作为可靠的训练集或最终准确率基准。它声称有 30 张，实际只有 26 行、20 个字面唯一引用；其中 6 行引用不存在文件，现存文件只有 15 个唯一图像，并且同一图像出现互相冲突的读数。开始宣称读数准确率前，必须先冻结一份经人工复核的无冲突评测清单。

## 2. 比赛约束转化为工程验收条件

比赛方案明确要求：

- 核心算法包含仪表定位、刻度识别和指针角度计算；
- 采用深度学习与传统机器视觉结合的路线；
- 轻量神经网络参数量不超过 100M；
- 训练数据至少覆盖 30 种不同品牌、不同量程，并包含正常、低照、强反光等环境；
- 陌生仪表类型识别准确率不低于 95%；
- 支持 RK3568、RK3576 等 ARM 边缘设备，单帧延迟不超过 300 ms，连续 100 次平均响应不超过 250 ms；
- 设备功耗不超过 5 W，硬件总成本不超过 2,000 元；
- 支持不少于 50 种指针表，包括圆形、方形、异形，以及 0-10 MPa、0-300 ℃ 等量程；
- 测试集整体读数准确率不低于 99%，陌生仪表类型不低于 95%；
- 原型需现场连续读取至少 5 种不同形态仪表；
- 开源代码必须标注来源并满足开源协议。

比赛文件没有定义“读数正确”的允许误差。99% 与 95% 在没有误差阈值、最小分度规则和拒识计分规则时不可复现，因此必须把第 7 节的评测口径写入技术报告，并尽早向赛事方确认。

## 4. 无需训练 YOLO 的端到端读数数据流

```mermaid
flowchart TD
    A[输入图像/摄像头帧] --> B[质量检查: 模糊 过曝 反光 遮挡]
    B --> C[冻结 best.pt 检测仪表 ROI]
    C -->|零检出| Z[detector_miss 并计入错误]
    C --> D[形态判断: 圆形 扇形 线性 异形]
    D --> E[椭圆/边框拟合与透视归一化]
    E --> F{已知实体或模板?}
    F -->|是| G[ORB/AKAZE 单应性匹配模板]
    F -->|否| H[OCR 识别数字 单位 正负号]
    H --> I[刻度线检测与数字-角度配对]
    I --> J[RANSAC/单调分段拟合 scale(theta)]
    G --> K[加载已验证标定参数]
    J --> L[指针候选提取]
    K --> L
    L --> M[轴心+RANSAC/Hough/PCA 求指针方向]
    M --> N{单针 双针 多圈 线性?}
    N --> O[角度或位置映射到数值]
    O --> P[置信度 物理范围 时序一致性]
    P --> Q[读数 单位 置信度 失败原因]
```

### 4.1 定位与归一化

1. 固定加载 `runs/detect/meter_yolov8n_final/weights/best.pt`，每图只保留最高置信度目标框并保留约 5% 边缘。
2. 检出后不能直接把裁剪中心当轴心。先用外圈轮廓、椭圆或矩形边框估计表盘平面。
3. 圆表倾斜时将椭圆仿射/单应性校正为标准圆；矩形表使用四边形单应性；扇形和线性表进入专用分支。
4. 输出归一化变换矩阵，后续所有轴心、刻度、指针坐标都在同一坐标系计算。

### 4.2 轴心、指针和刻度

- 轴心候选来自中心盖帽圆、径向线交点和模板轴心，不能只使用霍夫圆圆心。
- 黑色指针使用自适应阈值、细化和穿过轴心的 RANSAC/Hough 直线；红针可增加 HSV 颜色候选。
- 在极坐标图中，指针表现为跨半径的稳定峰；文字和刻度通常只占局部半径，可用径向连续长度过滤。
- 指针尖端取轴心沿候选方向的最远有效连通点，方向由长端、模板允许扇区和时序连续性共同消歧。
- 双针保留两个独立候选及颜色/宽度特征；M10 不允许在未指定语义时只返回最高分的一根。
- M09 的主圈角度和小圈圈数分别读取；如果小圈不可见，只能输出主圈相对位移并降低置信度。

### 4.3 模板优先的已知仪表路径

对生产现场已经安装的固定仪表，首次安装时保存：

```yaml
meter_id: site-A-pressure-01
shape: circle
pivot: [x, y]
direction: clockwise
scales:
  - unit: MPa
    min_value: 0
    max_value: 1.6
    min_angle_deg: 225
    max_angle_deg: -45
    minor_division: 0.02
pointer_policy: black
reference_features: ORB descriptors + reference image
```

运行时用 ORB/AKAZE 特征和 RANSAC 单应性将当前 ROI 对齐到模板，再使用固定标定曲线。模板必须来自独立校准图或人工点击的刻度端点，不能从待评测图片的真实读数反推，否则构成测试泄漏。

该路径计算量小、解释性强，适合 M05-M07 等结构重复的现场固定仪表。模板匹配失败时转入 OCR 泛化路径，不可强行套用相似外观但不同量程的模板。

### 4.4 陌生仪表的 OCR 自动标定路径

1. 将刻度环极坐标展开，定位数字候选和单位区域。
2. 使用轻量 OCR 识别数值、负号、小数点和单位；同一数字用多尺度/旋转候选投票。
3. 把数字框中心投影到拟合圆/椭圆，得到 `(angle, value)` 样本。
4. 至少需要 2 个可信数值点；3 个以上时用 RANSAC 排除 OCR 离群点。
5. 等分线性表使用线性映射，非均匀表使用保持单调的分段线性或 PCHIP 映射。
6. 双刻度表按径向层级聚类，分别拟合，例如 MPa 环和 psi 环；输出必须明确选择的单位。
7. OCR 标定结果按“表盘视觉指纹+量程+单位”缓存，连续帧只运行定位、对齐和指针几何。

若 OCR 数字不足、单位冲突或拟合不是单调关系，必须返回 `calibration_failed`，不能猜量程。

### 4.5 线性、异形和多指针分支

- M12 线性/竖直表：检测标尺主轴，使用指针投影坐标 `value=f(s)`，而非角度。
- 半圆/扇形表：轴心可能在 ROI 外缘，使用弧线拟合和径向刻度交点恢复轴心。
- 双针表：配置 `black`、`red` 或 `both`；若业务语义未知，结构化返回两个读数。
- 百分表：主针角度按模 360° 计算，小针/计数圈提供整圈数。
- 数字+指针混合表：数字显示不能自动当作指针真值，除非数据协议明确其含义。

### 4.6 置信度与时序

总置信度不应直接复用 YOLO 置信度，可组合：

```text
detection_confidence
geometry_fit_score
pointer_line_score
ocr_scale_score
template_match_score
temporal_consistency
```

连续视频使用中值滤波、最大变化率约束和短时多数投票。超范围跳变、指针候选突然换色、轴心漂移或模板匹配下降时输出低置信度或拒识。

## 5. 分阶段实现建议

### 阶段 A：可信最小闭环

- 冻结 YOLO 完成 ROI；
- 先选 5 种几何差异明确、单针、单量程仪表；
- 每种使用独立模板校准；
- 实现圆表、矩形弧表、扇形表三个几何分支；
- 输出读数、单位、各阶段置信度和可视化证据；
- 用修正后的独立评测图验证，不使用待测读数反向校准。

### 阶段 B：泛化和困难类型

- 加入 OCR 自动量程/单位识别；
- 加入双刻度、双针、全圆回绕和线性表；
- 引入反光、低照、旋转、透视和遮挡增强；
- 在“整块物理仪表留出”的陌生类型集合上评测。

### 阶段 C：边缘部署

- YOLO 和必要 OCR 导出 ONNX/RKNN，INT8 校准使用真实光照样本；
- OpenCV 几何保持 CPU/NEON 可运行；
- 模板命中时跳过 OCR；
- 分别记录采集、检测、几何、OCR、后处理耗时；
- 在目标 RK3568/RK3576 上做 1 次冷启动、100 次热运行和功耗测试。

## 6. 评测定义

### 6.1 数据划分

- 按物理仪表/产品型号/来源组划分，不能随机按图片划分；
- 同一仪表的连续帧、旋转图、压缩副本和近重复图必须放在同一 split；
- “陌生仪表”要求该物理仪表、模板、品牌/型号或量程组合不参与训练和模板校准；
- 模板路径与 OCR 泛化路径分别报告，不能混成一个无法解释的总数；
- 测试清单冻结后保存 SHA256，禁止边测边改模板。

### 6.2 读数误差

对量程 `[v_min, v_max]`：

```text
absolute_error = abs(prediction - ground_truth)
full_scale_error = absolute_error / (v_max - v_min)
division_error = absolute_error / minor_division
```

建议同时报告：

- MAE 和中位绝对误差；
- 平均/95 分位满量程误差；
- `<= 0.5`、`<= 1.0` 个最小分度的通过率；
- `<= 1% FS` 的通过率；
- 每种单位、形态、量程和光照条件的分组结果。

在赛事方给出正式规则前，内部主口径建议暂定为：预测单位和量程正确，且绝对误差不超过 **1 个最小分度**；无法可靠得到最小分度时，使用 `<= 1% FS`，并明确标注使用了替代规则。最终 99%/95% 必须按赛事确认口径重新计算。

### 6.3 端到端准确率与拒识

```text
end_to_end_accuracy = correct_readings / all_test_inputs
detection_coverage = detected_inputs / all_test_inputs
reading_coverage = numeric_outputs / all_test_inputs
selective_accuracy = correct_readings / numeric_outputs
```

用于比赛主结果时，`detector_miss`、`calibration_failed`、`pointer_failed` 和主动拒识均进入分母并视为未正确读取。可以额外报告 selective accuracy 展示质量门控价值，但不能用它替代端到端准确率。

对每张图必须保存：输入路径和哈希、GT 值/单位/量程/最小分度、检测状态、框、模板或 OCR 路径、轴心、指针角度、刻度映射、预测、置信度、耗时、失败原因和是否正确。

### 6.4 性能评测

- 单帧延迟应报告完整链路，而非只报告 YOLO；
- 分别报告模板命中和 OCR 冷标定的延迟；
- 100 次平均响应时间需使用同一设备、同一输入分辨率和固定预热规则；
- 同时报告 P50/P95/P99、峰值内存、功耗和温度；
- 明确相机采集、图像解码和可视化是否计入赛事延迟口径。

## 7. 主要失败模式与防护

| 失败模式 | 风险 | 检测/防护 |
| --- | --- | --- |
| YOLO 零检出或裁断表盘 | 后续几何无输入或缺少端点刻度 | 记录 `detector_miss`；检查边界接触并增加 padding |
| 强反光、过曝、模糊 | 指针和刻度消失 | 清晰度/饱和区比例门控，多帧选优，不盲目输出 |
| 透视倾斜 | 圆变椭圆，角度偏差 | 椭圆/边框拟合后归一化；记录重投影误差 |
| 把 ROI 中心当轴心 | M06/M08 等系统性偏差 | 中心盖帽、径向交点、模板三源融合 |
| 指针阴影、文字或刻度被当作指针 | 方向错误 | 要求候选穿过轴心并具有长径向连续性；时序约束 |
| 指针配重端方向反转 | 读数落到量程另一端 | 使用允许扇区、长端、尖端形态和模板方向消歧 |
| 黑针/红针、双针交叉 | 少读或读错目标针 | 分颜色保留多候选；配置返回 black/red/both |
| 双刻度/多单位 | 数字角度配错环 | 按半径聚类刻度环；单位绑定；分别拟合 |
| OCR 小数点、负号、单位误识别 | 量程放大 10 倍或符号反转 | 词法约束、量程先验、多候选投票和单调性检查 |
| 非均匀或反向刻度 | 线性插值错误 | 多锚点分段单调拟合；检测顺/逆时针 |
| M09 全圆回绕和圈数 | 主针角度无法确定绝对位移 | 同读小圈；否则仅报告相对读数和低置信度 |
| M12 线性/异形表 | 圆表算法失效 | 形态路由到线性坐标或专用模板 |
| 数字显示与指针共存 | 输出对象歧义 | 明确任务目标；数字和指针结果分字段 |
| 同外观不同量程 | 模板误匹配后系统性错误 | 模板匹配后必须核对 OCR 单位和端点值 |
| 错误/冲突 GT | 训练和评测结论无效 | 人工双人复核、路径哈希、冲突阻断和版本冻结 |

## 8. 当前必须补齐的数据

要形成可验证闭环，至少需要为每个评测图补充：

```text
image_path
image_sha256
meter_id / physical_meter_id
shape
ground_truth_value
unit
scale_min
scale_max
minor_division
target_pointer (black/red/both/main/sub)
ground_truth_source
review_status
condition (normal/low_light/glare/tilted/blurred/occluded)
known_or_unseen
```

优先动作不是继续训练检测器，而是：

1. 人工修复并复核 Markdown 中的 26 行，消除路径和读数冲突；
2. 从中选出至少 5 种可明确量程、单位和最小分度的单针仪表；
3. 为每种准备独立校准图与独立测试图；
4. 先跑通冻结 YOLO、模板标定、几何读数、误差报告的完整闭环；
5. 再用 OCR fallback 扩展到陌生表和双刻度表。

只有当评测清单无冲突、校准与测试严格分离后，“达到 80%”或赛事要求的 99%/95% 才是可解释、可复现的读数结论。
