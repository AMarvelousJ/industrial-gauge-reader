# 数据预标与审核 V1

`data_premark`将全部原始图片建立可审计记录，并从四类形态各抽30张组成120张人工审核集。四类是正视圆表、透视椭圆表、矩形/扇形弧表，以及异形/遮挡/偏心表。

拆分固定为每类20张开发集和10张冻结验证集。开发CSV/manifest位于输出根目录；冻结真值、全部预标记录和包含冻结路径的组合机器索引只位于 `frozen_private/`，二者不再混装。精确SHA-256、64位感知哈希与颜色直方图共同生成近重复簇；审核集每簇最多选一张，从构造上阻止近重复图片跨拆分。

自动预标包含表盘框和边界候选、形态分数、轴心、最多五条指针候选、候选角色、刻度弧及置信度。它们均是待审核候选。读数、单位、量程和最小分度字段保持为空，不从Markdown评测真值推断。

表盘框来自已有YOLO标注，只用于帮助人工预标，审计值为 `existing_yolo_label_for_annotation_only`。冻结端到端预测不得读取该框。重复聚类使用单链接并查集，存在相似链导致过度合并的局限；实际阈值、精确重复组、感知合并簇和最大簇均由 `audit.json` 披露。

人工审核完成前，这120张图片只能用于建立标注协议与验证工具链，不能作为算法准确率结论。冻结验证集的人工真值应由独立评测者保管。

审核验收由 `python -m data_premark.review_acceptance` 执行。审核CSV缺列、缺行、任意样本尚未完成或关键数值无效时，结果必须为 `not_ready`，几何和读数指标保持空值。

为避免冻结集反馈进入开发，未提供最终预测时，形态宏召回率、轴心误差和指针角度误差只在80张开发集上计算。最终预测使用读数器的 `sample_id/value/unit` 1.0接口，必须严格且仅覆盖40个冻结ID；评测器进行兼容单位换算后只报告聚合读数准确率，不输出逐条真值或误差。容差优先使用最小分度，缺失时使用量程跨度的1%；至少34/40才通过。
